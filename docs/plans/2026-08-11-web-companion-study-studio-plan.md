# StudyMate 网页桌宠与真实学习闭环方案

> 日期：2026-08-11  
> 状态：讨论方案，暂不实施  
> 适用范围：StudyMate Web、网页内桌宠、Study Studio、角色主题

## 1. 总体判断

- 方案整体可行。现有 React 前端，以及任务、Quiz、Grade、Buddy、掌握度和事件日志能力，已经覆盖大部分底层基础。
- 核心价值不是单纯增加可爱角色，而是缩短用户从打开产品到开始学习的距离，并把 `Ready → Focus → Quiz → Reflect` 变成连续闭环。
- 桌宠应作为 Agent 状态的轻量表达层，服务于陪伴感和反馈感；即使关闭桌宠，学习功能也必须保持完整可用。
- 第一阶段只考虑网页内桌宠，不引入 Electron、Tauri 等 Windows 桌面客户端技术。
- 当前四张原图可以作为角色动作素材来源，但现有精灵条存在抠图残边、裁切和动作跳变问题，不能直接作为正式资产上线。

## 2. 已确认的产品选择

- 桌宠形态：第一阶段采用网页内浮动 Companion Layer。
- 第一阶段目标：优先验证真实学习闭环，而不是只制作视觉演示。
- Focus 内容：原材料与 AI 解释并列，原材料是可信主内容，AI 解释按需生成。
- 角色正式显示名改为：芽团、晴川、凛川、柚宁。
- 后端稳定 ID 保持不变，避免破坏已有 Buddy 状态和聊天历史。

## 3. 关键实现方向

### 3.1 角色与视觉资产

- 同步角色配置、称呼、文案和设置页中的显示名称，但不修改后端角色 ID。
- 不把动作合集当作连续动画播放。
- 为每个角色制作统一画布的独立状态图片：
  - `idle`
  - `reading`
  - `thinking`
  - `working`
  - `success`
  - `concern`
  - `waiting`
  - `sleeping`
  - `waving`
- 使用透明 PNG 或 WebP，并通过角色状态清单配置资源映射。
- 桌宠主体只采用呼吸、轻微位移等 CSS 微动，并支持 `prefers-reduced-motion`。
- 建立统一的 Core Tokens。角色主题只改变色彩、环境背景、桌宠、微文案和动效，不复制页面或组件。

### 3.2 Today 与 Companion Layer

- 将 Dashboard 改为 Today Lobby，第一屏只保留：
  - Today Focus
  - 轻量学习进度
  - 一条可解释的 Agent Insight
  - 一个主要 CTA
- 移除右侧常驻 `BuddyPanel`，改成不遮挡内容的浮动 `Pet + PetBubble`。
- 完整关系、记忆、聊天和角色设置继续保留在 Buddy 页面。
- 默认使用“陪伴”模式，并支持安静和关闭；偏好写入现有 Buddy preferences。
- 桌宠状态必须由真实请求和学习事件驱动。网络或 LLM 失败时退回 `idle` 或 `waiting`，不能制造虚假学习状态。
- 使用本地事件衡量“打开到开始 Session 的时间”和“Session 完成率”，第一阶段不默认引入第三方分析服务。

### 3.3 Study Studio

- 新增 `/studio`，将现有任务、Quiz 和 Grade 串成连续流程：

```text
学习材料
  ↓
Recall
  ↓
Quiz
  ↓
Feedback
  ↓
Next / Reflect
```

- 当前任务默认选择今日第一个未完成的 `learn` 或 `review` 任务；如果只剩 Quiz，则直接进入测验阶段。
- Focus 同时提供两类内容：
  - 主内容：概念定义和 `relatedChunks` 对应的原始材料。
  - 按需 AI 解释：基于选中 chunks 生成讲解，并返回引用的 chunk IDs。
- AI 解释失败时，原始材料仍然可以正常阅读，不能阻断学习流程。
- 增加最小 Session 持久化，使刷新后可以恢复当前任务、当前阶段、开始时间和已完成内容。
- 学习任务完成继续复用现有任务完成逻辑。
- Quiz 和 Grade 继续复用 `gradeAndAdapt()`，避免重复实现批改、错题分析和掌握度更新。

### 3.4 Reflect

- Reflect 只汇总本次真实 Session 数据，不生成虚构指标。
- 首版展示：
  - 学习时长
  - 完成知识点数量
  - 答题数量
  - 正确率
  - 掌握度变化
  - 明日首项任务
- Reflect 是学习结束仪式，不应退化为复杂数据报表。

## 4. API 与数据接口

- 新增 Studio 聚合接口，返回：
  - 当前 Session
  - 当前任务
  - 概念定义
  - 经过安全过滤的关联材料
  - 下一学习阶段
- 增加 Session 的开始、阶段推进和结束接口，并为重复提交提供幂等处理。
- 增加按需解释接口，只允许前端提交 task、concept、chunk 等标识，由服务端解析内容。
- 不允许前端提交任意本地文件路径，也不向前端暴露 `sourceLink` 中的本机绝对路径。
- 扩展 Grade 前端类型，接收现有工作流产生的掌握度变化和计划调整信息。
- Reflect 从 Session 和 Grade 结果中汇总数据，而不是由前端临时推测。
- 追加以下事件，同时保持现有 Event schema 兼容：
  - `study_session_started`
  - `study_stage_completed`
  - `study_session_completed`

## 5. 可行性与主要风险

### 5.1 高可行部分

- Dashboard 减法和主要 CTA 调整。
- 用浮动桌宠替代右侧 Companion Rail。
- 根据现有角色 ID 切换角色资源和主题。
- 复用现有任务、Quiz、Grade、Buddy 和掌握度接口。
- 利用 `Concept.definition` 与 `Concept.relatedChunks` 展示有来源的学习材料。

### 5.2 需要新增能力的部分

- 当前后端没有完整的 Study Session 聚合对象，需要增加轻量应用层编排。
- Focus 的计时、刷新恢复和阶段推进需要持久化。
- Dashboard 的具体计划调整原因需要从现有工作流结果或事件中提取，而不是只显示笼统文案。
- AI 解释需要建立引用约束、失败降级和输出结构校验。

### 5.3 资产风险

- 原图是动作合集海报，不是规则网格精灵表。
- 当前处理后的横向精灵图存在明显色边、裁切和相邻动作污染。
- 不同动作轮廓差异很大，直接循环会产生跳变，不适合作为 idle 动画。
- 正式发布前需要确认原始角色图片的商业使用权和再分发权。

### 5.4 产品风险

- 如果桌宠过度活跃，会破坏 Focus Mode。
- 如果 AI 解释取代原材料，会增加事实错误和用户不信任风险。
- 如果第一阶段同时实现完整主题、所有动作和所有页面，容易稀释真实学习闭环的验证目标。
- 角色改名必须只改显示层和人格文案，不能直接修改稳定 ID。

## 6. 产品价值与验证指标

第一阶段最值得验证的不是“用户是否喜欢角色图片”，而是以下行为是否改善：

- 用户能否在进入首页后 3 秒内找到下一步。
- 从打开 StudyMate 到启动 Session 的时间是否缩短。
- 启动 Session 后的完成率是否提高。
- 用户是否能理解 Agent 为什么调整计划。
- 桌宠是否提供陪伴感，同时没有遮挡学习内容或制造打扰。
- 用户关闭桌宠后，完整学习流程是否仍然可用。

桌宠相关反馈应作为次级指标：

- 安静、陪伴、关闭三种模式的使用比例。
- 用户主动点击桌宠或进入 Buddy 页的频率。
- 桌宠主动干预后的继续学习率。

## 7. 实施分期

> P0 拆分为 P0a（入口与陪伴层）与 P0b（学习闭环）。原因：表现/资产层与行为/闭环层验证信号不同（前者"看起来对"、后者"数据对不对"）、失败回滚成本不同（P0a 不动后端数据、P0b 新增状态与接口），且入口（Today/桌宠）先行才能为 P0b 提供干净的行为验证样本。拆分不改变范围，只改变交付节奏。

### P0a：入口与陪伴层（不动后端数据，可整体回滚）

| 内容 | 验证信号 |
|---|---|
| 角色显示名迁移（改名清单含 4 个角色 JSON、`mock_llm.ts` 硬编码映射与台词、PRODUCT_INTRO.md、前端文案；后端稳定 ID 不变） | 显示层一致，mock 模式聊天回复同步新名 |
| Today 首页减法：第一屏收敛到一个主要 CTA | 首屏只有一个主要 CTA |
| 用网页浮动桌宠替代常驻 Buddy Panel | 桌宠不遮挡正文与主要按钮 |
| 桌宠状态接入前端请求生命周期（fetch 驱动 waiting/happy/concern） | 开启减少动态效果后动画停止 |
| 支持安静/陪伴/关闭三模式，偏好写入现有 Buddy preferences | quiet/companion/off 偏好正确保存 |
| 建立角色资产规范（9 状态清单 + 统一画布）；首批用现有 SVG portraits 支撑表现，不阻塞发布 | 规范文档确定，表现层可上线 |

### P0b：学习闭环（后端新增为主）

| 内容 | 验证信号 |
|---|---|
| 新增 `/studio` 与聚合接口，跑通 `Today → Focus → AI 解释 → Quiz → Grade → Reflect` | Mock LLM 跑通黄金路径 |
| 实现 Session 最小持久化（创建/恢复/阶段推进/结束），重复提交幂等 | 任务状态、掌握度、错题、计划调整、Session 记录真实落盘；刷新可恢复 |
| Focus 提供定义 + relatedChunks 原始材料；AI 解释按需生成，失败降级到纯材料 | AI 解释带合法 chunk 引用；失败时可继续阅读 |
| Quiz/Grade 继续复用 `gradeAndAdapt()`，前端 Grade 类型扩展带回 masteryChanges/adjustments/latestInsight | 响应不泄漏本机绝对路径 |
| Reflect 汇总 Session 与 Grade 结果 | 学习时长、知识点数、答题数、正确率、掌握度变化、明日首项任务 |
| 追加 `study_session_started` / `study_stage_completed` / `study_session_completed` 事件，保持 Event schema 兼容 | 事件可追加，旧事件可读 |

### P1：体验完整度

- 完成四套 Ambient Theme。
- 打磨 Reflect 和 Agent Insight 的原因解释。
- 补全完整桌宠状态资产与动画打磨。
- 增加 Growth 页面中的 Session 历史和趋势。

### P2：长期陪伴能力

- 活跃度分级：安静、陪伴、活跃。
- 高价值里程碑插画和漫画分镜。
- 评估 Windows 常驻桌宠，但不默认进入当前 Web 工程。

## 8. 验证方案

### 后端

- Session 创建、恢复、阶段推进和结束。
- 重复完成与重复提交的幂等性。
- 空计划、无关联 chunk 和材料损坏时的降级。
- AI 解释失败时仍可继续学习。
- 不向浏览器泄漏本地文件绝对路径。

### 前端

- Today 第一屏只有一个主要 CTA。
- 当前任务选择与阶段切换正确。
- Quiet、Companion、Off 偏好正确保存。
- 桌宠状态由真实请求和学习事件驱动。
- 页面刷新后可以恢复 Session。
- 移动端和窄屏下桌宠不遮挡正文及主要按钮。
- 开启减少动态效果后，持续动画停止。

### E2E

- 使用 Mock LLM 跑通完整黄金路径。
- 验证任务状态、掌握度、错题、计划调整和 Session 记录均真实落盘。
- 验证 AI 解释带有合法 chunk 引用。
- 验证完成 Reflect 后可以返回 Today 并看到更新后的状态。

### 资产

- 透明背景无明显绿色或粉色残边。
- 角色主体不被画布裁切。
- 不同状态的脚底、视觉中心和缩放比例一致。
- Focus 中没有持续跳跃或高频粒子动画。
